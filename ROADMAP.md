Геймифицированный курс Python «с нуля» для перехода в автоматизацию тестирования — от печати первой строки до фреймворка автотестов на реальном UI+API проекте.

- Репозиторий: https://github.com/mishkma/autoquest (ветка `master`)
- Сайт: https://mishkma.github.io/autoquest/ (GitHub Pages, деплой автоматически при пуше в `master`)
- Наглядная версия этой роадмапы (Claude Artifact): https://claude.ai/code/artifact/bb7fbbad-f3b5-4ad5-8c53-11d57b4416f4

**Прогресс: 14 / 16 модулей готовы** (+ 2 чекпоинта после М3 и М5). Этапы 1 и 2 полностью готовы.

## Платформа

- Структура: `index.html` + `css/style.css` + `js/interpreter.js` (свой Python-движок на JS, без Pyodide) + `js/modules-data.js` (контент модулей) + `js/app.js` (UI/состояние)
- Прогресс студента хранится в `localStorage` браузера (ключ `autoquest-state`)
- Тема сквозного проекта (AutoQuest Test Framework) — с модуля 4, реальный репозиторий/git/CI — с модуля 6+

### Ограничения интерпретатора (важно при написании новых заданий)

- списки/словари-литералы — только в одну строку, без переноса
- нет срезов (`x[1:3]`), только одиночный индекс (в т.ч. отрицательный)
- нет общего `in`, только `for ... in`
- у словаря нет `.items()` — только `.get()/.keys()/.values()`
- `min/max/.sort()` — только по числам
- функции без default-параметров, `*args`/`**kwargs`, multiple return
- **нет `class`, `import`, `try`/`except`** — модули 6+ (ООП, стандартная библиотека, pytest, exception handling и всё последующее, где нужен requests/Selenium и т.д.) целиком идут в реальном Python (см. ниже), не в браузерной песочнице

### Модули без браузерной песочницы (М6+)

С модуля 6 студент ставит настоящий Python и работает в VS Code — песочница дальше не используется вообще, потому что не поддерживает `class`/`import` (нужны для ООП, стандартной библиотеки, pytest, requests, Selenium и т.д.). Вместо `check(out)` там два типа задач:
- **`kind:'checklist'`** — самостоятельно отмечаемый шаг на своей машине (поставил/запустил/закоммитил); опционально показывает код через `starter`, если его нужно ввести/скопировать
- **`kind:'predict', offline:true, expected:'...'`** — то же самое, что обычный `kind:'predict'`, но ничего не выполняется в браузере (сравнение идёт с заранее known-correct выводом настоящего CPython, не с рантаймом песочницы)

Оба типа уже реализованы в `js/app.js`. Весь новый код для таких модулей перед публикацией стоит реально прогонять через `python` (или наш `js/interpreter.js` для обычных модулей) — не считать «на бумаге».

**М14 (Selenium)**: навигация/чтение (`get`, `find_element(s)`, `.text`, `.get_attribute`, `NoSuchElementException`) реально прогнаны через настоящий Chrome против живого automationexercise.com. `.click()`/`.send_keys()` в этой конкретной песочнице (Claude Code sandbox) не работают — синтетический ввод через WebDriver блокируется на уровне окружения (подтверждено: JS-манипуляция DOM работает, `.click()`/`.send_keys()` — нет), это ограничение именно этой изолированной среды, не сайта и не кода. У реального пользователя на обычной машине эти вызовы работают штатно — это стандартный, учебниковый Selenium API, просто не был лично прогнан построчно в этой сессии.

## Бэклог

- **готово** — Автодеплой: не требовался отдельно — сайт чистая статика на GitHub Pages без сборки, Pages сама публикует на каждый пуш в `master`. Пуш в `master` теперь делает Claude сам.
- **готово** — Перевести всё содержимое курса на английский (теория, задания, весь UI и сообщения интерпретатора). Завершено 8 сентября 2026.
- **план** — Добавить переключаемую локализацию на русский поверх английской версии.
- **после готовности всех 16 модулей** — Геймификация (визуал + история + вход + звук), одним пакетом:
  - **Визуал**: 8-битный стиль (модули = уровни, боссы = боссы игры; референс палитры/HUD — Contra/Battletoads/Double Dragon). Мини-превью уже одобрен (HUD, карточки уровней), блок кода нужно передумать под более «естественный» разработческий вид.
  - **История**: сейчас есть только визуальный язык (HUD, уровни, боссы), но нет сюжета — почему студент здесь, кто он в мире игры, что значит «босс» модуля в истории, что происходит на переходе между этапами (Python basics → автотесты → инструменты автоматизации). Нужно продумать краткий нарратив, который держится на существующей теме сквозного проекта (AutoQuest Test Framework, e-commerce на automationexercise.com) — не отдельная вселенная, а обёртка поверх неё.
  - **Вход как в игру**: стартовый экран (`view-path` сейчас открывается сразу как список модулей) — нужен вступительный экран/интро перед ним, ощущение "зашёл в игру", а не в сайт-курс.
  - **Выбор персонажа**: опционально на старте, без деления по уровню опыта (не "новичок"/"про") — чисто косметический выбор аватара/спрайта, хранится в `localStorage` рядом с `autoquest-state`.
  - **8-битная музыка**: фоновый чиптюн + звуки на события (задача пройдена, уровень открыт). Технически — процедурная генерация через Web Audio API (осциллятор), а не готовые mp3-файлы: не тащит лицензионные вопросы и не утяжеляет статику. Нужен mute-переключатель и старт по клику пользователя (браузеры блокируют автовоспроизведение звука без взаимодействия).
  - **Гейм-мастер и вступление уровня**: при входе в модуль текстовый брифинг от гейм-мастера — что за уровень, каких «мобов» (задачи) предстоит пройти, кто финальный босс (boss-задача). Технически — просто ещё одно поле в объекте модуля (`intro`) + модалка/карточка перед списком задач, рендерится один раз при первом входе (дальше можно скрывать/сворачивать).
  - **Артефакты за победу над боссом**: после решения boss-задачи модуля — награда (броня/оружие, тематически по 8-битному стилю), которая что-то даёт функционально, а не только косметика — например, больше подсказок за попытку, подсветка активной строки в примерах, скип одной задачи в домашке и т.п. Нужно продумать баланс, чтобы это не обесценивало обучение (не должно позволять проходить модуль без реального понимания). Хранится в `localStorage` вместе с прогрессом.
  - Технически всё реализуемо на текущем стеке (чистый HTML/CSS/JS, никакого бэкенда/сборки не требуется) — основной риск не технический, а объём контента (нарратив, тексты гейм-мастера, баланс наград нужно с нуля продумать и написать) и человеко-часы на пиксель-арт для интро/персонажей/артефактов.
- **после готовности курса** — Доступ для друга без claude.ai (вероятно решится само собой — сайт теперь на GitHub Pages, просто дать ссылку).
- **готово** — Апгрейд редактора кода: номера строк, подсветка синтаксиса и строки с ошибкой, автодополнение.
