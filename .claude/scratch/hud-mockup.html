LEVEL Rises automatically as your total XP crosses each threshold. A higher level doesn't unlock anything by itself — it's a running record of how much of the course you've cleared.
SYSTEM > Reading your HUD: LV rises as you earn XP from completed tasks, and 🔥 counts consecutive days with at least one task done. That's the whole panel — no hidden meters.
Click LV, the XP bar, or 🔥 above to open its explanation.
A

Tap-to-reveal card

The HUD stays exactly as compact as it is today. Clicking any cell opens a small corner-bracket card directly under it — the same panel language AutoQuest already uses for the reset-progress confirmation, just re-purposed as information instead of a warning. Closes on a second click or click-away.

States
  • Rest — identical to today's compact HUD
  • Open — one card at a time, closes the previous on a new tap
  • EN/RU — card text swaps with the language switch
Fits because
Reuses an already-approved motif (corner brackets, --a-bg1) instead of inventing new chrome — same reasoning that closed the side-margin and boss-header "empty space" issues.
Trade-off
Doesn't solve "understand without interacting" on its own — a first-time visitor still has to discover that the HUD is clickable at all. Works on tap as well as click, so it's the one option with a real mobile path later.
B

Icon-first HUD

Each cell gets a tiny pixel glyph (a level-up chevron stack, a spark for XP) standing next to the number, so the category reads from shape before anyone reads the abbreviation — closer to how a real arcade HUD (health icon, coin icon) works. A small ? next to each cell still opens the same detail card from Option A for anyone who wants the exact rule.

States
  • Rest — icon + number, no text label needed, ? visible but quiet
  • Open — same detail card as A
Fits because
Directly answers the requirement that the HUD should be readable "at a glance" rather than only on hover/tap — the icon carries meaning even if nobody ever opens a card.
Trade-off
New icon vocabulary has to be learned once too — just a faster, shape-based version of that same learning curve. Slightly busier HUD than today's, and 🔥 already does this job for streak, so only LV/XP gain new glyphs.
C

One-time briefing

The HUD itself never changes and carries no info affordance at all. Instead, the very first time someone reaches the topbar, a dismissible strip in the game-master's own SYSTEM > voice (identical framing to the real per-module briefing) explains all three readings in one line. Dismissing it — or simply not re-showing it after the first session — means it never comes back.

States
  • First visit — briefing shown, dismissible
  • Every later visit — briefing gone, HUD stays maximally compact
Fits because
Teaches once, in the voice the course already uses to explain new things (module entry, boss encounters), then gets out of the way — no permanent UI tax on returning students.
Trade-off
If someone dismisses it too fast, or forgets by module 8, there's no way back in short of a settings toggle — the least forgiving option of the three, and the only one that needs a stored "seen it" flag.
Recommendation

A + B combined: ship the icon glyphs from B (answers "readable without interacting" directly) with the tap-to-reveal card from A wired to the same cells, instead of the ? button — so the HUD looks slightly richer at rest, and tapping any cell (not just a small dot) gives the full rule for anyone who wants it. C's onboarding voice is worth keeping in reserve for something bigger later (e.g. the first time XP or a streak actually changes) rather than spent here.

All three drop the native title tooltip shipped in the last pass — none of them depend on hover, which was the actual problem with that version.

Open questions

  • Touch/mobile reveal — explicitly deferred per the approved requirements; A/B's tap-based card is the option that already has a path there once someone picks it up.
  • Exact glyph shapes for LV/XP in option B are placeholders here (chevron-stack / spark) — worth a quick second pass once a direction is chosen, same care as the per-signal boss silhouettes.
  • Should the detail card's copy match the three tooltip strings already shipped in i18n.js (hudLvTitle/hudXpTitle/hudStreakTitle), or does moving to a card change how much can be said (a card can hold a full sentence more comfortably than a tooltip)?
